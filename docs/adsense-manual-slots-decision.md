# AdSense 手動広告枠（レバーA）の判断メモ

最終更新: 2026-08-01

## 現状

- コード側は `<AdSlot>` が **55箇所に実装済み**（`components/ads/AdSlot.tsx` / `lib/adsense.ts`）
- 有効化は Vercel env **`NEXT_PUBLIC_ADSENSE_ENABLED=true` の1行**のみ。戻すのも env 削除だけ
- 2026-08-01 時点で **未設定＝手動枠は本番で0個**。本番HTMLに `<ins class="adsbygoogle">` が出ていないことを確認済み。自動広告（ローダー `pagead2.googlesyndication.com/.../adsbygoogle.js?client=ca-pub-4445473825791494`）のみ稼働
- 社長判断（2026-08-01）: **一旦様子見**。「広告はバランスが大事」

## 先送りしてよい理由

**AdSense の支払い設定（税務情報・本人確認・銀行口座）が未完了**のため、収益が発生しても受け取れない。この状態で広告在庫だけ増やしても、増えるのは未収の数字であって現金ではない。
最低支払額は ¥8,000。したがって正しい順序は次のとおり。

1. 支払い設定を完了する（社長のみ実施可）
2. 自動広告だけの素のページRPMを実数で把握する（AdSense → Sites → kyounoko.jp。**ホーム合算はほぼリメギフなので必ずサイト別で読む**）
3. その実数を見て手動枠を入れるか決める

## 判断日

**2026-09-01週**。既に同じ週に9月判定のタスクが2件（鳥貴族 kids-menu 面／一覧探索クラスタ）あるので、まとめて処理する。

### そのとき見る3つ

| 見るもの | 判断 |
|---|---|
| 支払い設定が完了しているか | 未完なら、まずそれ。広告枠の議論はその後 |
| 自動広告のみのページRPM（AdSense Sites） | 実数が取れていれば、手動枠の期待値を推定ではなく実測ベースで置ける |
| PVの伸びが踊り場に入ったか | 伸びている最中は、体験を変えて成長を鈍らせるリスクの方が大きい。横ばいになったら入れどき |

直近のGSC週次では 7/13週 1,358clk/日 → 7/20週 1,295clk/日 とわずかに下降しており、**すでに踊り場の兆しがある**。9月時点で横ばいが続いていれば、3つ目の条件は満たす。

## 入れると決めた場合の進め方

一気に55枠を開けない。**記事中1枠から**始め、下記のUX指標を前後比較する。

### ベースライン（GA4実測 2026-08-01・直近28日／前28日）

| 指標 | 直近28日 | 前28日 |
|---|---|---|
| PV | 60,473 | 12,405 |
| セッション | 43,298 | 8,918 |
| ユーザー | 39,902 | 8,231 |
| **PV/セッション** | **1.40** | 1.39 |
| **エンゲージメント率** | **0.596** | 0.598 |

PV/セッション 1.40、エンゲージメント率 0.596 が、広告を入れる前の基準値。
**収益だけを見て判断しないこと。**この2指標が明確に落ちるなら、収益が増えていても引き戻す。エンゲージメントの低下は最終的に検索順位に返ってくる。

取得コマンド:

```bash
node scripts/ga4-report.mjs --property=533628127
```
