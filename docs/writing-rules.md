# 記事を書く前に読むルール（きょうのこ）

**このファイルが存在しなかったせいで、1,109本の記事に同じ構造の誤りが入った。**
2026-08-19〜23の全面監査で出てきた実測をもとに、二度と同じことが起きないための規約をここに置く。

新しい記事を書くとき・既存記事を書き換えるときは、着手前にここを読むこと。
あわせて `docs/experiments-active.md`（進行中のSEO実験と凍結記事）も必ず見ること。

---

## 1. 体験談（`## 我が家のリアル`）に事実の断定を書かない

**書かないもの**: 金額 / 階数 / 貸出の有無 / 営業時間・休館日 / 台数 / 対象年齢の断定

これらは**本文の公式情報セクションが持つ**。体験談は体験に徹する。

  ❌ 「9階の授乳室が近くて助かった」
  ⭕ 「授乳室が同じ階にあって助かった」

**なぜ**: 2026-08-23の実測で、体験談に混入していた事実の**8割が「本文の公式セクションに既に
正しく書いてある事実の再掲」**だった。親切心で添えた数字が、公式の更新時に取り残されて古くなる。
サイト全体468本の体験談のうち**99本**がこの状態で、修正に丸1日かかった。

**実際に起きた事故**:
- モーニング3本で、体験談が4歳児のドリンクバーに198円を計上。**同じ記事の公式表は「未就学児無料」**
- 鴨川シーワールドで「入園9,600円」。記事の設定と本文の料金から計算すると**6,600円にしかならない**
- 上野動物園で「レンタル200円」。**自社の別記事は既に「200円ではありません」と書いていた**

**体験談そのものは資産なので消さない。** 運営者が実際に行った記録であり、公式が書けない情報
（「朝はほとんど乗らなかったのに昼を過ぎて一気に借りておいてよかったに変わった」等）は
そのままにする。削るのは検証可能な断定だけ。

**医療・安全は特に厳しく。** 「38.5℃で救急に行った」という体験は書いてよいが、
**「38.5℃を超えたら救急へ」という一般化した断定は体験談に置かない**（本文の免責つきセクションへ）。
`/editorial-policy` の「医療・健康は『医師・かかりつけ医にご相談ください』の免責を必ず付与」を割らない。

## 2. 施設を書く前に、実在を一次情報で確認する

2026-07に室内遊び場31本で**掲載施設の3〜5割が架空・閉店**、2026-08に水遊び記事で
**台東5/5・大阪5/6・品川4/5**が不良だった。実在しない公園・商業施設・店名を載せていた。

**確認の順序**:
1. **自治体のオープンデータ／GIS**で固有名を全数照合する（市の公園マップがArcGISなら
   REST APIを直接叩く。船橋で1,567フィーチャ・固有名997件を取得できた）
2. 無ければオープンデータCSV → 公式の一覧ページを全ページ取得
3. **運営元公式の店舗一覧**（チェーン店の場合）

**陽性対照を必ず取る。**「データに載っていない＝存在しない」と短絡しないため、
**同じデータソースが同種の対象を現に記録していること**を毎回確かめる。

  ⚠️ **東京都のオープンデータCSVは `備考` 列が全区で空**。大阪市の都市公園一覧xlsxも設備欄なし。
     **どちらも実在と住所の照合にしか使えず、設備の在否は証明できない**（各自治体の個別告知ページで見る）

**確認できない施設は、数を埋めるために残さない。本数より正確さが勝つ。**
船橋は6選→4選、吉祥寺は10選→6選、表参道は10選→5選に減らした。
**外した施設は「この記事から外した◯◯（公式に確認できなかったもの）」節で読者に説明する**
（その名前で検索して来た読者に「無い」と答えられる）。

## 3. 「エリアに複数店舗あり」と書かない

2026-08-22の実測で、駅別ランチ5本のうち**5本すべてでハズレ**だった。
丸亀製麺は吉祥寺にも池袋駅前にもなく、サイゼリヤは渋谷道玄坂にも表参道にもない。

**チェーン名＋エリア名から店舗の存在を推定しない。公式店舗検索で引いてから書く。**

再利用できる公式データ源（2026-08-22に確立・いずれもcurlで取れる）:

  モスバーガー  https://www.mos.jp/data/shop/shop.json （全国・市区町村コードで絞る）
  コメダ        https://eu.komeda.co.jp/v1/hp/shop?prefecture=東京都&brand_type=1
  丸亀製麺      https://stores.marugame.com/sitemap1.xml → 個別店舗ページ（全店の店名・所在地を全数照合できる）
  サイゼリヤ    https://shop.saizeriya.co.jp/sz_restaurant/spot/list?address=… （「検索結果：N件」で完全列挙）
  丸井          https://www.0101.co.jp/contents2/facilityinfo/<店番>/facility.json
  すかいらーく系 https://store-info.skylark.co.jp/api/point/{5桁geohash}/ （セル単位で全ブランド全店が返る。
                大井町は xn76e。ガスト/ジョナサン/バーミヤン/しゃぶ葉の在否を1リクエストで確認できる）
  ゼンショー系   maps.sukiya.jp / maps.hama-sushi.co.jp / maps.cocos-jpn.co.jp / maps.nakau.co.jp
                `…/jp/address.html?q=東京都◯◯区` で区ごとに全数照合できる
  b-map系      吉野家/ドトール/松屋/ロイヤルグループ/やよい軒は api/proxy2/shop/list?address=13109 型（区コード指定）。
                `?coord=緯度,経度&radius=1200&limit=100` の半径検索も使える
  マクドナルド  https://map.mcdonalds.co.jp/sitemap.xml で店舗コードを列挙 → /map/{code} を取得
                （個別ページはJS描画なのでsitemap経由が確実。設備アイコンはJSで一律出力＝各店の判定には使えない）
  スターバックス 検索APIは403だが `https://store.starbucks.co.jp/pref/tokyo/?city=◯◯区` と
                店舗詳細 `/detail-{id}/` は素のcurlで取れる
  CoCo壱番屋    https://tenpo.ichibanya.co.jp/api/point/ が**全国1,231店を無認証で一括返却**（座標・営業時間・座席数つき）
  KFC          https://search.kfc.co.jp/points/{id}
  レインズ系    https://map.reins.co.jp/{gyukaku|onyasai}/tokyo のHTMLに data-lat / data-lon / data-store(JSON) が全店分。
                くら寿司 shop.kurasushi.co.jp/tokyo も同じCanly系で同構造
  Canly新版     大戸屋 store.ootoya.com は一覧に件数しか無いが、詳細 `/detail/{storeId}/` に全データが入る

  ⚠️ 旧記載「ガスト・すかいらーく系は機械的に引けない」は**2026-08-31に反転**。旧 store.skylark.co.jp の
     話で、新ロケータ store-info.skylark.co.jp の point API で引ける（大井町の全数確認で実証済み）。
  ⚠️ 「無い」判定には**陽性対照**を必ず取る（同じAPIで別エリアの実在店が引けることを確認してから0件と書く）
  ⚠️ **b-map/NAVITIME系が返す緯度経度は数百m狂うことがある**（2026-09-01に神田エリアで実測。松屋 神田南口店は
     住所が千代田区鍛冶町2-1-2なのに座標は本石町付近＝三越前から136mを指した）。
     **距離の判定は座標を鵜呑みにせず、必ず住所の丁目で裏取りする。**
  ⚠️ **同じチェーンでも店舗ごとに条件が違う**。ベビーカー貸出の対象月齢は北千住マルイ＝生後10ヶ月〜2歳、
     錦糸町マルイ＝生後1ヵ月〜4才。「マルイなら借りられる」と一般化しない。

## 4. 「公式に記載がない」を「ある」とも「ない」とも書かない

確認できなかったものは **「公式に記載を確認できませんでした」** と書き、確認先（公式URL・電話）を案内する。

**数字を直せないなら、数字ごと削除して確認導線に置き換える**（2026-08-20にバーミヤンで採った方法）。
推測で新しい数字を書くのは、直している誤りを新たに作るのと同じ。

## 5. 動的描画のページでも数字は取れる

「JavaScriptだから確認できない」と諦める前に、**そのページ自身が読んでいるデータ**を探す。

  ピューロランドの料金      公式が読む一次JSON `common_v2/json/YYYYMM.json` に日別の価格帯・開園時刻
  しながわ水族館の休館日    JSの `addClass('close')` にべた書き
  鴨川シーワールドの料金    **旧料金表がHTMLコメント `<!-- -->` の内側**に残っていて、素で抜くと混ざる

curlがbot遮断される場合（ディズニー公式など）は、**ブラウザ自動操作**（`mcp__Claude_Browser__*`）を使う。
読み取りのみ。CAPTCHAが出たら突破せず中止する。

## 6. 期限のある情報には「賞味期限」を書く

会期・休止・キャンペーンは必ず終わる。**記事に期限を明示し、読者が自分で最新を確認できるURLを置く。**

  例: 東京ディズニーシーのベビーセンターは 2026年5月12日〜10月2日 休止
      → 各記事に「この記事の賞味期限：2026年10月2日」節＋公式URL、
        あわせて期限日に更新タスクを予約した

**タイトルに日付を入れたら、必ず更新タスクを予約する**（放置すると最も目立つ形で誤情報になる）。

## 7. 書き終わったら3つのガードを通す

```bash
node scripts/check-cross-article-facts.mjs   # 監査済み記事との食い違い（ERRORは0を維持）
node scripts/check-parking-claims.mjs        # 駐車場の断定に営業時間があるか
node scripts/check-internal-links.mjs        # 内部リンク切れ
```

`check-cross-article-facts.mjs` は**同じ施設について記事間で食い違っていないか**を見る。
「監査済み」の判定は**本文中の確認日**（`updatedAt` は一括加工でも動くので一次情報を当たった証拠にならない）。

  ⚠️ **「監査済みの記事だから正しい」とは限らない。** 2026-08-22に、監査済み2記事が
     「昭和記念公園は立川駅から徒歩15分」で一致していたが、**公式はゲートごとに違い**
     （あけぼの口10分／立川ゲート18分／西立川ゲート2分）、どちらも不正確だった

## 8. 出典の書き方

確認した項目には**出典URLと確認日**を添える。記事末尾に `## 出典` 節を置くのが標準。

  > 出典：東京都公園協会「舎人公園」公式サイトの駐車場欄
  > （https://www.tokyo-park.or.jp/park/toneri/ ）｜確認日 2026年8月20日

**引用した公式URLは、貼る前にcurlして200を確認する**（リンク切れの出典は出典ではない）。
