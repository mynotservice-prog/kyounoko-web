# サイトリニューアル 2026-09（読みやすさ・回遊性）設計メモ

最終更新: 2026-09-07 / ブランチ `renewal/ui-2026-09`

## 0. 目的と大原則

- 目的: **PV増**。手段は「サイト内の読みやすさ」と「回遊性（1セッションあたりPV）」の改善のみ。
  - 現状の最大の穴: 記事着地の PV/セッション 1.21（記事はサイト全クリックの 81.5%）。
- **SEO/GEO に影響を出さない**（厳守）。以下は変えない:
  1. URL・canonical・robots/noindex・title/description・OGP
  2. JSON-LD（Article/FAQ/Breadcrumb/Place/HowTo/ItemList…）
  3. 本文テキスト・見出しテキスト・見出しの階層（h1/h2/h3 のタグと順序）
  4. 画像 src（hero・本文画像・カード画像）— 新規画像は追加しない
  5. 既存の内部リンク（減らさない。**追加は可**）
  6. AdSense 枠（`<AdSlot>` の数と placement）・アフィリCTAの数
  7. `/today` の「クエリ→静的計算のみ」という性質（fetch/cookie/時刻依存を持ち込まない）
- 変えてよいもの: CSS、レイアウト、モジュールの見た目、**見出しタグでない装飾要素の追加**、
  回遊モジュールの追加（あわせて読みたい／ランキング／フッター／LINE／ホーム画面追加）、
  データに既にある項目の表示（例: スポットの駐車場・遊具・設備「なし」）。
- 添付モックは「イメージ」。既存資産に無い要素（住所・営業時間・館内エリア等）は**捏造せず出さない**。

## 1. 検証プロトコル（各ページ担当が必ず実施）

1. 変更前スナップショット: `scratchpad/snap-before/`（取得済み）。
2. 変更後: `node scripts/renewal/seo-snapshot.mjs snap <scratchpad>/snap-after-<page>` →
   `node scripts/renewal/seo-snapshot.mjs diff <before> <after>` で
   **title/description/robots/canonical/JSON-LD が identical、見出しの「-」がゼロ、リンクの「-」がゼロ、画像の lost がゼロ**を確認。
   テキストの「-」は、モジュール見出しの言い換え等の意図的なものだけ（理由を報告に書く）。
3. `npx tsc --noEmit`（自分の触ったファイルのエラーがゼロ）。
4. ローカル dev（http://localhost:3000）で 375px / 1280px のスクリーンショットを撮って目視。
5. `npm run build` は担当者は走らせない（統合後に COO が1回だけ実行）。

## 2. デザインシステム（第2版 2026-09-08 / 社長フィードバック反映）

第1版は「情報を丸角カードに詰め直しただけ」で完成モックと乖離していた。**第2版の指示（厳守）**:

### 2-1. 守るルール

| 項目 | 決定 |
|---|---|
| 地色 | 紙色 `#FBF5E8`。真っ白の面を作らない |
| 色 | 墨 `#25201B` / 紙 `#FBF5E8` / オレンジ `#EE7A2E` の3色＋濃淡のみ。**パステル多色カード・グラデーション・影は禁止**（色は写真に持たせる） |
| 丸角カード | **操作UIだけ**に許可: 入力欄 / 検索・CTAボタン / 日付切替 / 小さなステータス。**記事・ランキング・カテゴリ・設備情報・セクション全体はカード化しない** |
| 写真 | 角丸は軽く（`--kk-r-img` 6px）。全要素を丸いカードにしない |
| セクション区切り | 余白 / 細い罫線 / 写真サイズ / 文字サイズ で作る。カード背景で区切らない |
| 見出し | Klee One（`--kk-display`、少し手書き感のあるエディトリアル書体）。本文は Noto Sans JP。**見出しと本文で明確な表情差を作る** |
| 見出し装飾 | `＼` `／` オレンジ斜線・左のオレンジバー等は**すべて削除**。文字と余白だけで成立させる |
| PC / スマホ | 同じ見た目を引き伸ばさない。PCは余白・写真・段組を変える（`@media (min-width: 920px)`） |
| LINE・ホーム画面追加 | **スマホのみ表示**（920px 以上は非表示。kk.css で制御済み） |

### 2-2. 共通基盤（COO が用意済み。ページ担当は編集しない）

- `app/styles/kk.css` … トークン（`--kk-*`）＋ v2 トークンの上書き（影を `none` 化・面を紙色化）＋共通部品。
  - 部品クラス: `.kk-sec` / `.kk-sec-title`（装飾なし）/ `.kk-lead` / `.kk-btn`(.outline/.soft/.sm/.block) / `.kk-field` / `.kk-seg`+`.kk-seg-btn` / `.kk-chips`+`.kk-chip` / `.kk-pill`(.yes/.no/.text) / `.kk-fac-grid`+`.kk-fac` / `.kk-check`(.num) / `.kk-info` / `.kk-rows`+`.kk-row`（罫線区切り・枠なし）/ `.kk-tiles`+`.kk-tile` / `.kk-icon-tiles`+`.kk-icon-tile` / `.kk-line` / `.kk-home` / `.kk-footer` / `.kk-linecta`
- `components/kk/*` … `KkSectionTitle` `KkRowList` `KkFacilityGrid` `KkInfoTable` `KkCheckList` `KkLineCard` `KkAddToHomeCard` `KkFooter` `KkIcon`
- フォント: `app/layout.tsx` で Klee One(600) を `--font-klee` として追加済み。v2.css の M PLUS Rounded 1c は廃止し本文は Noto Sans JP に統一。Yomogi はトップのヒーローのみ。**新しいフォントを追加しない**
- `components/common/LineCta.tsx` はクラス化＋スマホ限定に改修済み（文言は不変）

**ページ担当が編集してよいのは自分のページの `.tsx` と `app/styles/<page>-v3.css` だけ。**
kk.css / v2.css / globals.css / layout.tsx / components/kk/* は触らない。

## 3. ページ別仕様（第3版 2026-09-08 / 社長指示の全文反映）

### 3-0. 全ページ共通の追加指示

- **地色は完全な白**（`--kk-paper: #FFFFFF`）。紙色の面は使わない。
- **絵文字を絶対に使わない**。`🌤 🍽 🧸 📍 👶 ☀ 📅 🎲 ⇄ ☔ 🚶 🗺 ♡ →` などの記号は
  すべて `components/kk/KkIcon.tsx`（社長支給のアイコンパック準拠・線画・墨1色）へ置き換える。
  自分のページと、自分のページだけが使う lib の定数（例: `lib/outing-plan.ts` のラベル）も対象。
- **文字は大きく・太く**。本文 15.5〜16px / 行間 1.9 前後、見出しは Klee One で本文と明確な差をつける。
  細い文字（font-weight 400 の小さい注記だけで構成する等）を避ける。
- **丸角カードを確実に無くす**。丸角は「入力欄 / 検索・CTAボタン / 日付切替 / 小さなステータス」だけ。
- **アイコンはテキストと意味が一致すること**（例: 「水族館」に魚、「公園」に木）。
- LINE ブロックはモック準拠の1ブロック（`KkLineCard`。バッジ＋見出し＋1文＋緑ボタン）。PCでは非表示。
- 「ホーム画面に追加」は1タップで追加画面（または追加手順）が開く（`KkAddToHomeCard` 実装済み）。
- **役割ごとにレイアウトを変える**。同じ色・文字・余白ルールを使いつつ、
  設備＝スペック / 魅力＝番号付きリスト / 基本情報＝表 / 詳細＝編集本文、のように表現を分ける。

### 3-1. スポット詳細 `/spot/[slug]`（基準 = ASOBono! モック）

「施設データベース」ではなく「出かける前に読む編集ページ」に見せる。既存情報は消さない。

1. **ファーストビュー**: パンくず → 施設名(H1) → 駅・アクセスの簡潔な情報 → メイン写真 → 必要なタグ。
   施設名をカードの中に入れない。写真を主役に大きく。過剰な角丸にしない。
2. **導入文**: 既存の施設説明をそのまま、写真の下に普通の本文として置く。新しいキャッチコピーを作らない。
   **文は改行して読みやすくする。文字サイズを大きく。**
3. **子連れ設備**（最重要・必ず4項目を視覚的に即確認できる状態で残す）:
   授乳室 / おむつ替え台 / 多目的トイレ / ベビーカー貸し出し。
   白背景に4項目を横並び、各項目は「アイコン → 設備名 → あり/なし」。**項目間は細い縦線のみ**。
   4枚の独立した丸角カードにしない。アイコンと設備名は墨色。
   色を付けるのは状態だけ（あり=オレンジ #EE7A2E / なし=グレー）。設備ごとの色分け・オレンジ背景は禁止。
4. **ここがうれしいポイント**（魅力）: 設備の直後。`01 02 03` の番号＋文章（`.kk-numlist`）。
   番号のみオレンジ、本文は墨、地は白、必要なら上下に細い罫線。**設備と同じUIにしない**。
5. **基本情報**: 住所・最寄り駅・営業時間・定休日・料金・駐車場・公式サイトなど**現在あるデータ**を維持し、
   **データテーブル（四角で組んだ表）**として見せる（`.kk-info`）。設備とも魅力とも別UIにする。
   料金詳細も同じく表で。
6. **年齢別の楽しみ方**: 0〜1歳 / 2〜3歳 / 4〜6歳 を維持。巨大なカード3枚にしない。
   年齢を左（またはPCでは左列）に強く出し、その横に本文。**アコーディオンか改行で読みやすく**。
7. **館内エリア・過ごし方・実体験**（ベビーカー動線 / 混雑 / 授乳おむつ / 滞在時間 / 注意点 /
   混雑を避けるコツ / アクセスのコツ）は削除しない。すべてをカードにせず、
   H2 → 本文 →（必要なら小見出し）→ 罫線 の通常の編集記事として処理する。
8. **PR・関連導線**: アソビュー / じゃらん / 関連スポット / 周辺情報 / 関連記事 / LINE MAP は維持。
   役割ごとに分ける（PRは独立、関連記事は記事リスト、周辺はスポットリスト、LINEは独立CTA）。
9. **禁止**: 存在しない設備・情報・写真・CTAの追加、設備項目の変更、設備の多色カード化、全セクションの同一カード化。

### 3-2. 記事詳細 `/article/[slug]`（基準 = スシロー記事モック）

検索から来た人が最初の1〜2スクロールで答えを得られることを最優先。SEOテンプレ感を減らし雑誌記事に。

1. **ファーストビュー**: パンくず → カテゴリ等の小情報 → H1 → 著者・公開日・更新日・読了時間 → 通常のメイン写真。
   写真の上に巨大文字を重ねない。バナー加工しない。記事にない写真を追加しない。
2. **冒頭**: 導入文の後に検索意図への答えを早く出す。装飾カードを並べず、
   **結論を短く整理した情報ブロック**として見せる。強調に必要な分だけオレンジ。
3. **年齢別情報**: 既存の 0歳/1歳/2歳/3歳以上 を維持。巨大な色付きカードにしない。
   年齢表示を強く（数字にオレンジ可）、本文は静かに。
4. **設備・実用情報**: 記事内にベビーチェア・離乳食・おむつ替え等がある場合、スポットページと同じデザイン言語。
   存在しない項目を補完しない。
5. **我が家のリアル・実体験**: 小さなラベル＋本文。上下の余白や罫線で編集部コメントのように見せる。
   巨大な色付きカードにはしない。
6. **「ここまで読んだ人が、次に迷うこと」**: 関連記事カード3枚にしない。
   疑問をそのまま選べる**テキスト中心の次の行動リスト**にする。
7. **末尾の回遊**: 優先順位をつける（同チェーンの記事 → 他チェーン比較・子連れ外食 → 今日のプラン）。
   すべてを同じ強さでカード化しない。メイン導線を強く、その他は静かなリスト。
8. **PR**（mogumo・アソビュー等）は維持。本文に紛れ込ませず、PR表記を明確にした独立ブロックに。
9. **FAQ・出典**は維持。FAQのアコーディオン機能を壊さない。出典は末尾に静かに。
10. **禁止**: 存在しないCTAの追加（例「スシローの店舗を探す」）、本文途中への写真追加、
    メイン写真のバナー化、見出し横のオレンジ斜線、全H2の色付きカード化。

### 3-3. 今日の流れ・作成 `/today`（条件入力）

トップの検索をさらに詳しく設定する画面として見せる。**駅一覧ページに見せない**。生成ロジックは変更しない。

- 大見出しは「今日のプランをつくる」。無意味な説明コピーを足さない。
- 登録済みの子どもの年齢を表示（トップと同じ子どもの顔アイコン可）。巨大な設定カードにしない。
- 日付は 今日 / 明日 / 週末 を横並び。選択中だけオレンジ、未選択は白＋細い枠線。**トップと完全に同じ操作感**。
- 駅は既存の検索・入力・選択の仕組みを維持。入力欄の横幅を広く取る。
  主要駅 / よく使う駅 / 最近使った駅は現在のデータだけを表示。
  **駅名を大量の丸角チップで画面を埋め尽くさない**。必要な選択UIだけ軽く区切る。
- 主CTAは1つに絞って強く（オレンジ・横幅十分・「この条件で今日のプランを見る」）。

### 3-4. 今日の流れ・結果 `/today?station=...`

**現在の機能をすべて維持**（午前/昼/午後・各スポット・時間・移動情報・別候補・昼だけ一覧・
1日の動線を地図で見る・ネット予約PR・保存・別の流れ・雨の日代替・条件変更）。
横長カードの連続を「1日の時間軸」として再設計する。

1. 冒頭に「今日の流れ」＋駅＋登録年齢＋天気。「条件を変更する」も残す（巨大な設定フォームは再表示しない）。
2. 午前・昼・午後は**一本の縦タイムライン**。左に時間軸（オレンジの細い縦線＋時刻）、右にスポット情報。
3. 各スポットは名称・説明・設備・別候補を維持。写真は**現在データに存在する場合のみ**表示（新規作成しない）。
   スポット全体を大きな丸角カードにせず「タイムライン上の1つの予定」に見せる。
4. 設備情報（キッズメニュー・ベビーカーOK等）は維持。アイコン＋名称＋状態を簡潔に。パステル多色にしない。
5. 「別の候補に変える」は残すがメインCTAにしない（小さなテキストボタン程度）。「お昼だけ一覧で見る」も維持。
6. 移動情報（「◯◯駅直結」「◯◯駅まで歩いてすぐ 約0.8km」等）は**カード化せず**、
   スポットとスポットの間に 歩行アイコン＋距離＋所要時間 として置く。
7. 「1日の動線を地図で見る →」はタイムライン直後に独立した横長導線。機能CTAなので多少の背景色は可。
8. ネット予約PRは地図導線の後、プラン本体と十分な余白を空けて。PR表記を明確に。タイムラインの一部に見せない。
9. 「この流れを保存」と「別の流れを見る」は同格にしない。主ボタンと副ボタンを視覚的に分ける。
10. 「雨ならこっち」は残すが強くしない（雨アイコン＋短い説明＋矢印程度）。
11. 最後に「別の条件・駅で探す」への再検索導線。

### 3-5. トップ `/`

発見・入口。写真と編集的なレイアウト中心。ファーストビューはモックの検索UIに合わせる。
「スポットの種類から探す」の各タイルは**アイコンとテキストの意味を一致**させること。
