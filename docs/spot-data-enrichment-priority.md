# スポットデータ拡充 優先リスト

## 目的

`app/spot/[slug]` 個別ページは、情報スコア3点以上のスポットのみ indexable にしている。
スコアアップにより indexable スポット数を増やせば、SEOカバレッジが拡大する。

## スコアリング基準（lib/spots.ts と app/spot/[slug]/page.tsx の `isIndexable`）

| 条件 | 点数 |
|---|---|
| `note` 25字以上 | +1 |
| `facilities` 2項目以上設定 | +1 |
| `pricing` 設定あり | +1 |
| `hiddenTip` 15字以上 | +1 |
| `nearestStation` 設定あり | +1 |
| `ward` or `city` 設定あり | +1 |

**3点以上で indexable**。

## 拡充の優先順位

### 第1優先：人気スポット（popular: true）

すでに popular フラグが立っているスポットは検索ニーズが高い。
**まず popular スポットを全件 indexable に**するのが最優先。

確認方法（必要なら手動でリストアップ可）：
```bash
grep -B2 'popular: true' lib/spots.ts | head -50
```

### 第2優先：東京23区の主要スポット

東京23区は最大の検索ボリューム。とくに：
- 上野動物園、葛西臨海水族園、井の頭公園、しながわ水族館 などの定番
- 各区の代表公園・施設

### 第3優先：関西・神奈川・千葉の人気スポット

東京以外の主要観光地。
- ユニバーサル・スタジオ・ジャパン
- 海遊館
- 横浜アンパンマンこどもミュージアム
- 東京ディズニーリゾート（千葉）

### 第4優先：駅周辺のスポット

`nearestStation` が設定されているスポットは「駅×条件」検索からの流入が見込める。
未設定なら追加。

## 拡充すべき項目（優先順）

### 1. `note`（必須に近い）

例：`note: '幼児向けエリア充実。0歳から楽しめる屋内遊戯室あり。'`

「ChatGPT等のAIで自動補完」も可能だが、誤情報リスクのため最終確認は必須。

### 2. `facilities`

```yaml
facilities:
  bathroom: 'yes'
  diaperChange: 'yes'
  nursingRoom: 'yes'
  kidsSpace: 'yes'
  strollerRental: 'no'
```

実際の公式サイト・口コミで確認して設定。

### 3. `pricing`

```yaml
pricing:
  adult: '2,300円'
  elementary: '1,100円'
  preschool: '400円（3歳以上）'
  infant: '無料'
```

公式サイトの最新料金で。

### 4. `hiddenTip`

例：`hiddenTip: '平日午前10時前なら待ち時間ゼロ。年パス（5,000円）が2回で元取れる。'`

これが「他サイトにない独自情報」になり、SEO価値が高い。

## 自動化アイデア

### A. 公式サイトスクレイピング（要法令確認）

各施設の公式サイトから「料金」「営業時間」「アクセス」を取得。
robots.txt 確認＋手動レビュー必須。

### B. クラウドソーシングで実訪問取材

ココナラ・ランサーズで地域別に取材依頼：
- 1スポット ¥1,000〜¥3,000
- 写真・施設チェック・所要時間レポート

これで **「実体験ベースの一次情報」** が手に入り、E-E-A-T最強。

### C. ユーザー投稿募集（中長期）

サイトに「行ってきた！レポート」投稿フォームを設置。
ユーザーから情報が集まる仕組み。

## 実施工程

1. **今月**：上位10スポットの note・facilities を手動で追加
2. **来月**：人気カテゴリ別（公園・水族館・動物園）に20スポットずつ拡充
3. **3ヶ月後**：indexable スポット 200件達成
4. **6ヶ月後**：indexable スポット 400件達成

## 効果見込み

- indexable スポット 100件 → 月+5,000 PV
- indexable スポット 400件 → 月+30,000 PV
- 各スポットページから関連記事への回遊 → 全体PV増
