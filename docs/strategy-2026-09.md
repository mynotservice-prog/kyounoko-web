## 0. 結論（1文）

**目標は「日本の子連れ外食データの引用元になる」こと。** 被リンク・AI引用・指名検索・Google順位は、
すべてこの一つの活動から発生する。数値目標は **年内（12月）30万PV → 月100万PV**。
手段は43チェーンDBを記事の裏側から表に出し、**調査 → 内部リンク → 調達型ページ量産**を同じ配管で回すこと。

### 初版（同日）からの変更点

| 論点 | 初版 | 改訂2版 | 理由 |
|---|---|---|---|
| 目標 | 収益（月¥18〜30万） | **PV（年内30万・将来100万）** | 社長方針。収益はPVに従属させる |
| 中核の言い方 | 「被リンクを取って順位を上げる」 | **「引用元になる」** | 同じ活動から被リンク・AI引用・指名・順位が全部出る。手段より目的で置く方が意思決定がぶれない |
| 43チェーンDB | 記事の裏側の参照データ | **表に出す一次データ資産**（調査・引用・API的な提供） | SEO記事の素材で終わらせない |
| 公式サイトからのリンク | 「公式写真提供の型にリンクを条件として乗せる」 | **削除。取り下げる** | ⚠️ 下記 §9 |
| 記事の量産 | 一律に「やらない」 | **調達型セルに限り再開**（GSCで需要確認 → 調達型だけ） | 「何でも作る」の否定であって「作らない」ではない。初版の書き方が強すぎた |

### ⚠️ 取り下げる推奨（初版の誤り）

初版 §4 エンジンB に書いた **「公式写真提供の型に、公式の子連れ案内からの参照を条件として乗せる」は取り下げる。**
Googleのリンクスパムポリシーは**商品・サービスとリンクの交換**を明示的にスパムとして挙げており、
「写真を提供する代わりにリンクを張ってもらう」はこれに該当しうる。手動対策のリスクを、
参照ドメイン数個と引き換えに負う価値はない。

**置き換え**: 調査データと設備情報を**チェーン公式・自治体・メディアに「使ってもらう」**設計にする。
出典表記のガイドライン（引用フォーマット・CSV・図版）を用意して使用ハードルを下げ、
**リンクは要求せず、結果として参照される**状態を作る。見返りを条件にした瞬間に施策の性質が変わる。

## 3. 成長モデル（100万PVの分解式）

```
月間PV = 稼働セル数 × 1セルあたり月間クリック × (1 + 非検索セッション比率) × PV/セッション
```

「セル」= **エンティティ（チェーン・施設）× 条件軸（キッズメニュー／子供料金／ベビーチェア／離乳食持込／
座敷個室／子連れ攻略／ベビーカー／アレルギー／おむつ授乳）** の1マス。調達型ページの単位。

| パラメータ | 現在 | 年内30万PV | 月100万PV |
|---|---:|---:|---:|
| 稼働セル数 | **181** | 350〜400 | **1,700〜2,000** |
| 1セルあたり月間クリック | 約80〜140 | 130〜180 | 250〜300 |
| 非検索セッション比率 | +230%（内訳不明） | 同等 | 同等以上（AI・指名の増分） |
| PV/セッション | 1.25 | 1.55 | 1.6〜1.7 |
| **月間PV** | **9.4万** | **30万** | **100万** |

**この式が戦略のすべて。** 100万PVは「記事をたくさん書く」ではなく、
**セル数を約12倍 × 1セルの実力を約2.5倍**という2軸の掛け算でしか届かない。
そして1セルの実力を2.5倍にする入力が、被リンクとAI引用と指名検索＝**研究機関化**である。

## 5. 研究機関化 ── ①②③は3つの仕事ではなく、1本の配管

社長案の①調査 ②内部リンク ③調達型量産は、**43チェーンDBを中心に置くと同じ配管になる**。
別々のワークストリームとして走らせると3倍のコストがかかるので、順序を1つにする。

```
[ 0. DB化 ] 48エンティティを chain-facilities に取り込む（公式照合を1回だけやる）
        │
        ├─→ [ ① 調査ページ ] DBの横断集計＝追加取材ゼロで作れる一次データ
        │         └─→ 育児メディア・ニュース・自治体・チェーン公式が参照
        │
        ├─→ [ ② 内部リンク ] 調査ハブ → 外食カテゴリ → チェーン → 条件セル（4層）
        │         └─→ 外部評価を調達型セルへ流す。単答型（モーニング）には流さない
        │
        └─→ [ ③ 調達型セル ] DB駆動で654セルを埋める（表・確認日・出典が自動で入る）
```

### 5-0. 先に DB化（供給の律速はここ）

**記事の量産で律速になるのは執筆ではなく公式一次情報の照合。**
2026-09-04のスプリントは12エージェント並列で133本を2日で編集できたが、
その工数の大半は公式サイトのcurl照合だった。一方、DBに入っている43チェーンは
**セル単位で照合済み・verifiedAt付き**なので、そこから生成する記事の照合コストはほぼゼロ。

→ **未登録エンティティのDB化が、①②③すべての前提。** ここに最初の3週間を使う。

**調査ページの要件（これを満たさないと引用されない）**

1. **方法論**: 調査対象n・調査期間・調査方法（公式サイト照合／店舗公開情報／実訪問）・除外基準
2. **セル単位の出典URLと確認日**（DBが既に持っている。これが machikurabe 等の競合に対する差）
3. **再現可能性**: 集計スクリプトの説明。数字の出し方を隠さない
4. **CSV/表の配布**と**引用フォーマットの明示**（「出典: きょうのこ『◯◯調査2026』URL」）。
   リンクは要求しない（§9）
5. **図版**: 引用されやすいのは表ではなく1枚の図。OGPと本文に同じ図を置く
6. **更新方針**: 年次更新を明言（毎年参照される資産にする）

- ⚠️ 被リンク数を数えるときは `lib/auto-internal-links.ts` の描画時注入が .md に現れないことに注意
  （grepすると過小評価になる）。

## 6. 算数の訂正 ── 「200本 × 月1,500クリック = 月30万クリック」は5〜10倍の過大

方向は正しいが、この見積もりのままだと10月末に「計画未達」に見えてしまうので、実測で置き換える。

**実測: 1ページあたり月1,500クリックは、サイト最上位クラスの数字。**

| ページ | imp（90日） | pos | CTR | 月間クリック換算 |
|---|---:|---:|---:|---:|
| gusto-kodzure-koryaku | 45,325 | 5.9 | 1.65% | **249** |
| bikkuri-donkey-kids-menu | 38,577 | 5.3 | 2.23% | **287** |
| burger-king-kodzure-koryaku | 29,783 | 5.2 | 2.17% | **215** |
| kfc-kids-menu | 16,892 | 7.2 | 1.60% | **90** |
| 1〜4位帯の平均（11本） | 7,629 | ≤4 | 15.7% | **399** |
| 4.5〜6位帯の平均（26本） | 5,557 | 5前後 | 6.5% | **120** |

出所: `docs/experiments-active.md` §5 / `reports/rank-pushup-2026-08-27.md`

**つまり「3位圏に入って、CTRが2桁になった調達型ページ」でも月250〜400クリックが標準。**
月1,500クリックは王将クラス（サイト最上位1〜2本）の実力で、200本の平均値には置けない。

**訂正後の見積もり**

| 前提 | 200セル | 800セル | 1,750セル |
|---|---:|---:|---:|
| 平均150clk/月（現実的な立ち上がり） | 3.0万 | 12.0万 | 26.3万 |
| 平均250clk/月（3位圏まで押し上げ後） | 5.0万 | 20.0万 | **43.8万** |

**月100万PVに必要な検索クリックは約40〜45万/月。** それを満たすのは
**「1,750セル × 250クリック」＝ 稼働セルを現在の約11倍にする**という水準。
91エンティティ×9軸（819セル）では**足りない**ので、100万PVを本気で狙うなら
**エンティティ軸を約300へ広げる**のが必須条件になる（300×9＝2,700セル、稼働率65%で1,755セル）。

**エンティティ拡張の候補**（すべて「子連れで行くか判断が必要な固有名詞」）:
ラーメン・うどん・そば／カフェ・ドーナツ・アイス／回転寿司・寿司／焼肉・しゃぶしゃぶ・ビュッフェ／
弁当・定食／フードコートを持つモール（イオン・ららぽーと・アリオ）／
レジャー（水族館・動物園・遊園地・温泉）／空港・駅・SA/PA。
既に記事のある48エンティティ（IKEA・コストコ・ディズニー・羽田・レイクタウン等）はその入口。

## 9. リンク獲得のコンプライアンス（この線を越えない）

Googleのリンクスパムポリシーは、**商品・サービスの提供とリンクの交換**を明示的にスパムとして挙げている。
少人数運営が手動対策を受けたら回復に半年かかる。**割に合わないので、線を明確にしておく。**

| やらない | やる |
|---|---|
| 写真・掲載・データ提供と引き換えにリンクを要求する | データを**無償で使ってもらう**（見返りを条件にしない） |
| リンクを条件にした相互掲載・記事交換 | 引用フォーマット・CSV・図版を配布して**使用ハードルを下げる** |
| 有料リンク・リンク付きプレスの購入 | プレスリリースは**配信自体が目的**（リンクはnofollowでも構わない。露出→指名→AI引用が本命） |
| 「リンクしてください」の営業メール | 「この調査、御社の子連れ案内の更新に使えます」の情報提供 |

**測る指標も変える。** 参照ドメイン数だけを追うと上の線を越えたくなるので、
**「引用された回数（リンクの有無を問わない）」**を主指標にする。ノーリンクの言及でも
AI引用と指名検索には効く。

**環境の制約（2026-09-10 に実測）**: クラウドのセッションには `credentials/` が無く、
外部ホストへの HTTPS が組織ポリシーで拒否される（`connect_rejected`）。
つまり **GSC/GA4 の取得と公式サイトの照合はローカル実行が必須**。
クラウド側でできるのは、スクリプト・記事・DBコードの作成と、リポジトリ内データの集計まで。

既存の実験判定日は動かさない: 9/16・9/24・9/30・10/05・10/21（`docs/experiments-active.md`）

### ③ の実行コマンド（ローカル）

```bash
node scripts/traffic-mix.mjs --md=reports/traffic-mix-2026-09-11.md --json=/tmp/mix.json
# 期間を変える場合: --days=90 / GA4プロパティ: --property=533628127
```

出力に入るもの: GSCクリックとGA4セッションの同一期間突合（全体比・Organic Search比）／
チャネル別セッションとPV/セッション／source-medium 上位40（AI・検索・SNS・直接に自動分類）／
Direct の着地ページ上位20。**判断の分岐は Organic Search ÷ GSCクリック** で、
1.0〜1.3 なら健全（乖離の主因は非検索チャネル）、2倍以上なら計測側を疑う。
