## 2. SEO方針（全PR共通・index/noindex判断の単一の真実源）

> 背景：本サイトはAdSense「低品質コンテンツ」で不承認 → 薄ページ剪定（index 5136 → station×条件を ~1482 にゲート、`lib/station-cond-index.ts`）を継続中。
> **改修の大原則＝クロール可能な"価値あるHTML"は増やす、しかし新しい薄い/重複ファセットURLはindexに入れない。**

### 2-1. index させる面（canonical 自己参照）
- スポット詳細 `/spot/[slug]`、記事、`/spots`、**`/spots/[cat]`（カテゴリ全件）**。
- 都県×カテゴリ等の派生を index したい場合は、**必ず `station-cond-index.ts` と同型の二段ゲート（matched件数 ≥ 閾値 ＋ エリア規模）で需要のある組合せだけ**。全 area×cat の自動 index は禁止。

### 2-2. index させない面（`robots:{index:false,follow:true}` ＋ canonical→親）
- **filter/sort/page などクエリ変種は全て noindex,follow**。既存 `/today` の作法をそのまま踏襲（`app/today/page.tsx` L76-77 = `robots:{index:false,follow:true}` ＋ `canonical:'/today'`）。
- `follow:true` によりクローラは変種経由でもスポット詳細まで到達 → **「全件到達」と「index衛生」が両立**。
- 仕様書の「フィルタ・並び替え・ページを全てURLクエリに反映（共有・戻る）」は、変種を noindex,follow にすれば**UX共有性を保ったまま**達成できる。**各PRのmetadataで明文化する。**
- ページング `?page=2+` は noindex,follow（or canonicalをpage1へ）。

### 2-3. タスク別のSEO効果と地雷
| タスク | 効果 | 地雷/注意 |
|---|---|---|
| P0-3a カテゴリ全件 | **全計画で最大の正レバー**（841/853件がUI到達不能→クロール/内部リンク解放） | 派生ページは 2-1 のゲート必須 |
| P0-3b/c フィルタ・並び替え | 回遊・UX | **ファセットURLのindex膨張が最大リスク** → 2-2 を初日から作り込む（後付け禁止） |
| P0-1 今日の流れ | — | `/today`は既に index:false。param追加もSEO影響なし |
| P1-1c チェーン除外 | 薄い/重複除去・勝ち記事へ集約（純プラス） | チェーン毎にGSC確認→301/410/noindex |
| P1-8 口コミ(UGC) | **低品質不承認への直球＝最高ROIの信頼シグナル**。独自コンテンツ/鮮度/E-E-A-T/滞在 | (a)実件数が付くまで AggregateRating schema を出さない (b)承認制でやらせ/薄い投稿を排除 |
| P1-3 画像 | 実写化で信頼 | 実在施設名のAI偽写真は「スケールされたコンテンツ」/信頼リスク。「※イメージ」で低減 |

## 3. ストレージ決定（P1-8 口コミ／写真）

**結論：Vercelで確定。既存の Vercel KV(Upstash Redis) ＋ Vercel Blob をそのまま再利用（新規インフラ不要）。Neonは使わない。**

- 既存配線：`lib/kv-store.ts`（`@vercel/kv`＝裏はUpstash Redis、`KV_REST_API_*`/`UPSTASH_*` env、未設定時フォールバック付）、`lib/blob-store.ts`（`@vercel/blob`）。admin編集のデプロイ不要化で導入済。
- Neon不採用理由：無料枠のアイドル停止/コンピュート上限が来やすい。Upstashはリクエスト課金・サーバーレスで承認制の低頻度書込に好適。
- **マッピング**：
  - 写真 → **Vercel Blob**：アップ時にサーバ側で**EXIF位置情報除去**＋リサイズ圧縮（画像がコスト主因）。3枚×5MB上限。
  - 口コミ本体 → **Upstash Redis**：`review:{spotId}`=承認済リスト / `review:pending`=モデレーションキュー / `rate:{ipHash}`=INCR+EXPIREでIP制限 / `rating:{spotId}`=★平均キャッシュ（承認時に再計算）。
  - リレーショナル不要（追記・読取・承認の単純モデル＝キー単位リストで十分）。
- **注意**：Upstashはコマンド数課金 → スポットページで毎回 pending キューを全読みしない（承認済のみキャッシュ読み）。無料枠~1万コマンド/日は初期十分、伸びたら監視。
