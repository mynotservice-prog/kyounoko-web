## エグゼクティブサマリー

きょうのこは、Next.js 15 上に**極めて完成度の高いSEOインフラ**（JSON-LD、IndexNow、AI検索クローラー対応、redirect整理、サイトマップ分割）を備えた、開設5ヶ月目の子育てメディアです。技術基盤の質は同業の個人メディアでは突出しており、コードレビュー観点での「致命的な穴」はほぼありません。

一方で、データを見ると **「勝ち筋は明確に見えているが、3点のボトルネックで成長が頭打ちになっている」** 状態が見て取れます。

| # | ボトルネック | インパクト |
|---|---|---|
| **B1** | LCP 7.3秒（モバイルLab） | 順位の上限を抑え、CTR/離脱を悪化 |
| **B2** | 順位6〜10位 × 0クリックのクエリが10本超 | 月数百クリック分の機会損失 |
| **B3** | 新規率98.8% / scroll・clickイベント未発火 | 「読まれているか」を測れず改善が回らない |

これら3点と、それに連なる打ち手を以下にまとめます。優先度は **すぐ効く × 工数小** を基準にしています。

## 第2部 — 改善打ち手

優先度は「効果 × 着手しやすさ」で **P0（今週）／ P1（今月）／ P2（次フェーズ）** に分類しています。

### 2.1 SEO流入の増加

#### P0-1. CTR最適化スプリント（順位6〜10位の高imp/低CTRキーワードに集中）

**対象記事と新タイトル/メタの方向性**：

| URL | 現状の課題 | 新タイトルの型 |
|---|---|---|
| /article/kodzure-saize-koryaku（318imp / CTR 3.1%） | 「攻略」が抽象的でクリック動機にならない | **「【サイゼリヤ 子連れ完全攻略】ベビーカー入店・キッズメニュー・離乳食持ち込みの可否（2026年最新）」** |
| /article/shabuyou-kodzure-koryaku（255imp / CTR 3.5%） | 「しゃぶ葉」を見出し前半に置いていない可能性 | **「しゃぶ葉に赤ちゃん・子連れで行ける？ベビーカー／離乳食／キッズ皿｜2026」** |
| /article/jonathan-kodzure-koryaku（243imp / CTR 2.5%） | 「離乳食」「お子様ランチ」「キッズメニュー」を1記事でカバーしている割にタイトルが弱い | **「ジョナサン子連れガイド｜離乳食持ち込み・キッズメニュー何歳から・ベビーチェア」** |
| /article/gusto-kodzure-koryaku（244imp / CTR 1.2%） | 同上、特にCTRが低い | **「ガスト 離乳食・お子様メニュー・ベビーカー入店ガイド【2026】」**（"離乳食"を最前面に） |
| /article/bamiyan-kodzure-koryaku（168imp / CTR 2.4%） | 「2歳」「1歳」など年齢クエリにマッチしていない | **「バーミヤン 1〜2歳メニュー＆ベビーカー入店【子連れ完全ガイド】」** |

**コツ**：
- titleの前半30文字に**店名 + 検索者の悩みワード**（離乳食、ベビーカー、キッズメニュー、何歳から）を置く。
- meta description には「結論」「持ち込み可否」「対象年齢」を1文目に書く。Googleが書き換えても、AI検索（ChatGPT, Perplexity）はmeta descriptionをそのまま参照する傾向がある。
- 既存記事のtitle変更は、`generateMetadata` でfile-baseのフロントマターから `title` を拾っているので、各 .md の `title:` を編集するだけで反映可能。

#### P0-2. 「○○ 離乳食」「○○ キッズメニュー 何歳から」FAQをHowTo/FAQPage化

現在 schema-enhancers.ts は Recipe / Course しか付与していない。SERP特徴の **「他の人はこちらも質問」「FAQリッチリザルト」** を取りに行く。

各チェーン店記事の末尾に、

```yaml
faq:
  - q: ガストで離乳食は持ち込めますか？
    a: 多くの店舗で持ち込み可能ですが、店舗により対応が異なります。事前確認をおすすめします。
  - q: ガストのキッズメニューは何歳から？
    a: お子様メニューは概ね小学生以下を対象としています…
```

を追加し、`getExtraSchemasForArticle` で FAQPage JSON-LD を出力。

**期待効果**：上位3クエリ（"何歳から"系）に対してリッチリザルトが当たれば、表示領域が増えてCTRが体感1.5〜2倍。

#### P0-3. 「検出 - インデックス未登録 73件」の解消

未登録ページの多くは「人気記事への内部リンクが薄い」可能性が高い。

- カテゴリトップから新記事に **「最新の○○」「○月の新着」セクション**で内部リンクを張る。
- 既存上位記事の末尾「関連記事」枠（CrossLinkCards）に、未登録記事を意図的に差し込む。
- IndexNow は postbuild に組み込み済みだが、Bing/Yandexにしかpingしていない可能性。Search Consoleの「URL検査 → インデックス登録をリクエスト」を **週次で20件ずつ消化**する運用ルールに。

#### P1-1. 駅別ページ（/station/*）のSEO戦略を再設計

現状、駅別ページが Search Console で表示こそ取れているが、月間クリック1未満が多数。

提案：
- **/station/[駅名]/baby** 系（条件絞り込み）は3件未満で noindex 済みで適切。
- 一方、**/station/[駅名]** トップ（条件なし）の方は、駅周辺の子連れ事情をまとめた「セミ記事」化が必要。具体的には、駅の基本情報＋トップ3〜5スポット＋関連記事リンク＋駅周辺の「困った別解」（雨の日／ベビーカー連れ／個室）を3〜5行ずつ加えるだけで、薄いページ判定を回避できる。
- 23区中心ではなく、Search Consoleで実際にimpを取れている **駒沢大学・浅草橋・四谷・新宿** から優先的にテコ入れ。

#### P1-2. AI検索（ChatGPT/OAI）からの流入を増やす施策

現在13%取れているのは出色の結果。これを伸ばす施策：

- **冒頭150字に「結論ファースト」サマリーブロック**を全記事に追加（"## 結論（先に知りたい人へ）" は既にyayoiken等で導入済み、これを全記事に水平展開）。AIは記事冒頭を引用しやすい。
- **/llms.txt** が既に存在（app/llms.txt）。中身を「サイトの強み・対象読者・記事カテゴリの一覧」に最適化する。
- 記事末尾に「**この記事を要約してAIに渡す**」用の **構造化された5行サマリー** を入れる。Perplexity, Claude, ChatGPTが引用しやすくなる。
- Pinterest連携は metaタグだけ既に入っているが、**実際にPinterest経由の流入は計測されていない**。Pinterest投稿運用が始まっていないなら、月10ピン×子育て関連で開始すると、視覚SNS流入が増える可能性。

### 2.2 UX / サイト技術改善

#### P0-4. LCP 7.3秒の解消

最重要。モバイル基準でこの数字は、検索順位の上限を抑えている可能性が高い。

**仮説の優先順位**：
1. **ヒーロー右側 `today-card` の中の `dateLine`（formatJaLong(now)）と TODAY ラベル**がLCP要素になっているのでは。
2. 絵文字／emoji-twemoji フォントのフォールバック描画。
3. TodayFinder（client component）のhydrationコスト。

**やること**：

```bash
# Lighthouse のLCP要素を特定
npx lighthouse https://kyounoko.jp/ --form-factor=mobile --output=html --output-path=./lighthouse.html
# DevTools の Performance タブで LCP marker を確認
```

具体的改善案：
- **ヒーローCTA／today-card を Server Component に**（HeroCTA は A/Bテストでclient化が必要だが、card自体は静的でOK）。
- `<Image priority>` をヒーロー画像に明示。current page.tsx ではヒーロー画像のpriorityが見えない。
- TodayFinder の lazyhydrate（hydrate を first interaction まで遅延）。
- **Above-the-fold CSS をインライン化**。Tailwind の preflight + 必要クラスだけを critical.css として `<style>` に。
- `app/api/og` の動的OGP生成が初回アクセス時に重い場合、`unstable_cache` で1日キャッシュ。

ターゲット：**モバイルLCP 2.5秒以内**。スコアで言うと82→92。

#### P0-5. クリック/スクロール イベント計測の修復

GA4 click イベントが28日で6件しか発火していない＝**実質計測されていない**。

確認順序：
1. `lib/ga4-events.ts` を開き、`gtag('event', 'click', ...)` がどこから呼ばれているか確認。
2. HeroCTA, AffiliateLink, CTA系のonClickハンドラで、`gtag` 直叩きではなく内部ヘルパー経由になっているか。
3. SPA遷移時に `page_view` がGoogle SDK標準では発火しない。`next/router` の `routeChangeComplete` で手動 `gtag('config', GA_ID, { page_path })` を入れる必要がある（layout.tsxで現状なし）。
4. **scroll** はGA4のデフォルト「拡張計測」設定で90%スクロール時に発火する。Search Console 1ページ目を取れている記事の縦尺が短すぎる可能性も。記事長を確認しつつ、25%/50%/75%/100% のカスタムscrollを実装する手も。

#### P0-6. A/Bテスト発火の修復

`hero-cta-2026-05` の ab_assignment が28日で1件。`HeroCTA` client component の `useEffect` 内で `localStorage.getItem` → なければ `Math.random()` で割り当て → `gtag('event', 'ab_assignment', { variant })` の流れだと思いますが、おそらく：

- `gtag` がまだ初期化されていない（Script `afterInteractive`）タイミングで発火しようとして失敗。
- もしくは `window.dataLayer` への push のみ行われ、`gtag('event'...)` が呼ばれていない。

対応：`lib/ga4-ab.ts` を確認し、`window.gtag` が undefined のとき `window.dataLayer.push({ event: 'ab_assignment', variant })` でフォールバック。SSRガードも必要。

#### P0-7. /admin/* を GA4 から除外

- GA4 → 管理 → データストリーム → 拡張計測機能 → 詳細設定 → **内部トラフィックの定義** で `/admin/*` の path filter を作成し、`traffic_type=internal` を割り当て。
- データフィルタで `internal` を除外。
- これだけで指標がクリーンになる。

#### P1-4. H1のキーワード最適化

トップページ H1：「親の毎日を、ちょっと軽く。」

ブランドメッセージとしては完璧ですが、SEO観点では**子育て関連の主要キーワードが1語も入っていない**。

提案案（H1自体を変えるのが嫌なら、`<h1>` 直後に **`<h2>` でキーワード入りサブタイトル** を入れる）：

```html
<h1>親の毎日を、<span class="accent">ちょっと軽く</span>。</h1>
<h2 class="lead-keyword">子育て家庭の「今日どうする？」を、天気・年齢・予算で3分で決める</h2>
```

この `h2` に "子育て" "今日どうする" "天気 年齢 予算" を含めることで、ブランド名検索以外のクエリでホームが拾われやすくなる。

#### P1-5. アクセシビリティ 89 → 95+

Lighthouseで指摘されるのは概ね：
- カラーコントラスト（ベージュ系の細字、`#FBF5E8` 背景に対する補助文字）
- ボタンの aria-label
- リンクテキストの説明性

UA改善はSEOにも効く（包括的アクセシビリティ評価のシグナル）。

### 2.4 コンテンツ戦略

#### P0-10. 既存「攻略」記事を**離乳食・キッズメニュー・ベビーカー入店の三本柱に再構成**

Search Console を見る限り、ユーザーの主要関心は3つに収束：

→ 各チェーン店の「攻略」記事内に、この3つを **目次の最上位に**置く。h2見出しを：

```
## 結論（一覧表）

## キッズメニューは何歳から？
## ベビーカー入店・ベビーチェアは？

## 行く前のチェックリスト
```

の固定フォーマットに揃える。

#### P1-8. 「比較記事」を増やす — 「○○ vs ○○ 子連れで使い分け」

検索意図がまだ獲得できていないが、確実に需要があるクエリ：
- "やよい軒 サイゼ 子連れ どっち"
- "ファミレス 離乳食 持ち込み 比較"
- "子連れランチ チェーン店 ランキング 2026"

これらをカバーする「比較記事」を月2本ペースで追加。**既存記事への内部リンクハブ**として機能し、SEO的にも記事群を結束させる効果がある。

#### P1-9. 「ながみー」の専門性（E-E-A-T）を可視化

著者ページ（/about, /authors）が既に存在しsameAs / Organization で構造化済み。さらに：
- 各記事に **「この記事を書いた人」のミニカード**（顔写真 + 一言プロフィール + Twitter/Instagram）を末尾に。
- editorial-policy ページの内容を「実際にどう取材したか」「どう更新するか」具体例つきで強化。
- Google が E-E-A-T を見るシグナルとして、**著者ページ単体のSEO**（"ながみー 子育て" などで検索された時にプロフィールページが上位に来る状態）を作る。

#### P2-3. 動画コンテンツ（YouTube Shorts / Instagram Reels）の素材化

既存記事の中で**実体験ベース**のもの（やよい軒、サイゼ実訪問記）から **15秒のリール素材を月3本** 切り出す。YouTubeEmbed コンポーネントが既にあるので、撮影さえできれば記事に埋め込んで滞在時間と E-E-A-T が同時に向上。
