## 1. 結論サマリー

**きょうのこは「子連れおでかけサービス」としては現時点で成立していない。しかし「子連れ外食の攻略メディア」としては、実測データで勝ちが証明されている。この事実を受け入れ、外食に全張りするのが最速の道。**

- 6月実績: 検索クリック2,324/28日（前月比19倍）、CTR 9.6%、最終週は週1,518クリックで加速中
- 流入の実質100%が「チェーン店名×キッズメニュー/子連れ設備」。スポットページの検索流入はほぼゼロ、指名検索もゼロ、Discoverもゼロ
- つまり市場が答えを出している: **「おでかけ先を探すサービス」は誰にも求められていないが、「王将に子連れで行けるか」の答えは強く求められている**
- 勝ち筋: チェーン外食×子連れ設備×年齢別のDBを日本一にする → 0〜2歳の外食不安層を掴む → 生協/宅配食材など高単価アフィで収益化 → LINEで再訪資産化 → 12ヶ月後にチェーン本部・食品メーカーへのB2B
- 月100万は12ヶ月では届かない。現実的には6ヶ月で月3〜5万、12ヶ月で月10〜30万。月100万は24ヶ月＋B2B収益が前提

## 2. 現状の強み・弱み

### 強み（データで実証済み）
1. **「1クエリ1ページ独占」の勝ちパターンを持っている**。王将キッズメニューでpos2.8/CTR35.9%。この再現方法（専用記事×タイトル分離×カニバリ排除）が言語化・実証済み
2. **公式サイトが答えない質問に答えている**。「やよい軒 子供椅子」CTR45%、「サイゼ ベビーチェア」CTR28%——チェーン公式はベビーチェア有無・離乳食持ち込み可否を公開しない。ここが構造的な空白
3. **AI運用体制**。記事生成スキル・GSC分析スクリプト・デプロイ不要編集・薄ページ自動ゲートまで整備済み。少人数でも記事供給がボトルネックにならない
4. **収益導線が既に点灯**。VC（ホットペッパー¥110/予約、アソビュー3.3%）、じゃらん、A8生協申請中
5. モバイル比率95%＝ターゲット（外出先・キッチンで調べる親）と合致

### 弱み（はっきり言う）
1. **プロダクトとしての利用実態がない**。696スポット・4,700超の駅×条件ページを作ったが、検索流入ゼロ・回遊/再訪の証拠なし。「サービス」は現状、願望であって事実ではない
2. **ブランドが存在しない**。「きょうのこ」指名検索は90日で表示2回。ユーザーは記事を読んで去る。メディア名を覚える理由を1つも提供できていない
3. **収益単価が低すぎる**。ホットペッパー¥110/予約では、月1万クリックでも数千円。今の流入×今の単価では事業にならない
4. **スポットDBは負債化リスク**。鮮度管理コスト・施設からの修正依頼・品質バラつき——維持コストがかかるのに流入ゼロ。AdSense不承認の一因でもある
5. **AdSense2回不承認**＝Googleから「有用性の低いコンテンツ」の烙印。量産系ページの整理は進めたが、信頼回復には時間がかかる

## 3. 市場・競合分析

### 市場性
- 子連れおでかけ市場: 検索需要は巨大だが、いこーよ・Google Map・Instagramで満たされ切っている。後発が正面から入る隙はない
- **子連れ外食の実用情報市場: 空白**。食べログ/ぐるなびは「子供OK」フラグ程度で、ベビーチェアの台数・離乳食持ち込み・ベルト付きか・座敷の有無・キッズメニューのアレルゲンまでは持っていない。チェーン公式も店舗差を公開しない。ここに一次調査で入る価値がある
- 需要の質: 0〜2歳の親の外食は「行けるか分からない不安」が支配的。検索は来店直前・切実・行動に直結＝収益化しやすい意図

### 競合別の勝敗
| 競合 | 勝てない部分 | 勝てる部分 |
|---|---|---|
| いこーよ | スポット網羅・UGC・ドメイン権威。おでかけDBで正面勝負は不可能 | 外食は手薄。年齢×設備の実用密度 |
| Google Map | リアルタイム性・口コミ量・経路。単店舗情報では絶対勝てない | 「チェーン横断の子連れ比較」はMapにできない。Mapは店を決めた後、きょうのこは決める前 |
| Instagram | ビジュアル発見・ママ垢の信頼 | 検索性ゼロ・情報が構造化されていない。「◯◯ 離乳食持ち込み」の答えはIGでは探せない |
| 食べログ/ぐるなび/Retty | 店舗DB・予約導線・権威 | 子連れ設備の粒度。「子供可」の一言で終わっている |
| EPARK/ウォーカープラス | イベント・クーポンの規模 | 恒常的な実用情報の深さ |
| チェーン公式 | 一次情報の正確性 | 公式は「ベビーチェアありません」と書かない。親目線の横断比較・正直な弱点記載 |

**結論: 「Google MapとIGで済む情報」＝スポットの基本情報・写真・口コミ。「きょうのこでしか得られない情報」＝チェーン×店舗×年齢×子連れ設備の構造化比較。後者だけをやる。**

## 4. 勝ち筋候補

### 案A: 子連れ外食特化（チェーンDB化）— ★採用
- 勝てる理由: 実測で証明済み。競合空白。公式が出さない情報の一次調査は模倣コストが高い
- 弱点: 収益単価が低い。チェーン数は有限（〜100チェーン）で天井が見える
- 必要コンテンツ: チェーン攻略×残り30〜50本、比較ハブ（離乳食持ち込み一覧・ベビーチェア一覧・座敷一覧・アレルギー対応比較）、年齢別ハブ（0歳外食デビュー等）
- 必要機能: 既存で足りる。構造化データ（テーブル）の徹底のみ
- 収益化: ホットペッパー予約＋**生協/宅配食材（0〜2歳親と完全一致、CPA¥1,000超）**＋持ち物系物販
- SEO相性: ◎（実証済み） / 少人数: ◎

### 案B: 0〜2歳特化（赤ちゃん連れ全般）— ★案Aの拡張として採用
- 勝てる理由: 現流入の中心クエリ（離乳食・ベビーチェア・授乳・ベビーカー）が既に0〜2歳。不安が最も深く、情報単価が最も高い層
- 弱点: 卒業が早い（2年で読者が入れ替わる）→ LINEで取り続ける仕組みが必須
- 収益化: ◎（生協・こどもちゃれんじ・ベビー用品と全部合う）

### 案C: 条件検索（雨の日・駅近）× おでかけ — 次点（6ヶ月後）
- 勝てる理由: 「雨の日 子連れ」系は季節性需要が実在。「今日の流れ」機能と噛み合う
- 弱点: いこーよ・ウォーカープラスが強い。スポット情報の鮮度負債を抱える
- 判断: 外食記事内から「食後に行ける近くの雨の日スポット」として従属的に展開。単独では戦わない

### 案D: 地域特化DB — 後回し（12ヶ月後に判断）
- 勝てる理由: 「圧倒的に詳しい1エリア」は理論上勝てる
- 弱点: 実地調査コストが少人数運営と根本矛盾。今のスポットページ流入ゼロが答え
- 判断: 施設営業（公式写真提供）で関係ができたエリアだけ、受動的に深める

### 案E: 施設公式情報の整理・比較特化 — 案Aに吸収
- チェーン外食に限定してやる。全ジャンルは鮮度負債で死ぬ

## 6. SEO戦略

### 狙うキーワード群（優先順）
1. **チェーン名×子連れ設備**（離乳食/ベビーチェア/授乳/座敷/子供椅子/取り分け）— 勝率最高・即着手
2. **チェーン名×キッズメニュー×年齢**（「ココス キッズメニュー 1歳」型）— 実証済み
3. **比較・一覧ハブ**（「離乳食持ち込みOK ファミレス」「ベビーチェアあるチェーン」）— チェーン記事の束ね役
4. **年齢×外食**（「0歳 外食 いつから」「1歳 外食 メニュー」）— ハブとして
5. （6ヶ月後）**駅名×子連れランチ** — 需要ゲート(station-cond-index)を通る駅のみ

### 狙わないキーワード群
- 「子連れ おでかけ」「◯◯県 子連れ スポット」等のビッグワード（いこーよの牙城・権威不足）
- 施設名単体（公式とGoogle Mapに勝てない）
- 育児一般（「離乳食 進め方」等。外食文脈を離れたら専門メディアに勝てない）

### キッズメニュー流入の活かし方
入口(キッズメニュー) → 同チェーン攻略記事 → 比較ハブ → 「近くで食後に行ける場所(今日の流れ)」→ LINE登録。**全記事にこの4段導線を機械的に敷く**

### テンプレート・内部リンク・E-E-A-T
- 検索意図別テンプレ: ①即答型（設備クエリ: 結論を最初の1画面に表+根拠写真）②攻略型（チェーン: 年齢別セクション+設備表+失敗ポイント）③比較型（一覧表+個別記事リンク）
- 内部リンク: チェーン記事⇄比較ハブ⇄年齢ハブの3層。孤立記事ゼロを監査スクリプトで担保
- E-E-A-T: 全記事に「最終確認日+確認方法（実訪問/公式確認/電話確認）」を明示。運営者ページに実訪問の証拠写真。施設公式写真の提供を受けたら「公式提供」バッジ＝信頼の外部証明
- 誤情報対策: 記事frontmatterに`verified_at`を持たせ、6ヶ月超をリストアップ→月1で公式サイト照合（AIで差分検知→人間が確定）。修正依頼フォームを全ページに常設

## 7. コンテンツ戦略（スポット/店舗ページの理想形）

設計思想: **「施設紹介」ではなく「外出前の不安つぶしチェックリスト」**。親は説明文を読みたいのではなく、GO/NO-GOを判定したい。

### ページ構造（上から順に）
1. **判定ボックス（1画面目）**: 「0歳○/1歳◎/2歳◎…」「ベビーカー: 入店可・通路狭め」「授乳室: なし(隣のイオンにあり)」「離乳食持ち込み: 可(公式確認済み)」「最終確認: 2026-06」— 表で即答
2. **失敗ポイント**（他メディアが書かない差別化の核）: 「11:45以降は入店待ち30分」「ベビーチェアはベルトなし・腰すわり前は不可」「エレベーターが裏側で分かりにくい」
3. 年齢別の楽しみ方/食べられるもの
4. 親の負担情報: 滞在時間目安・混雑時間帯・疲労度・兄弟連れ適性
5. アクセス: 駅からベビーカーでの実動線（エレベーター位置）・車なし可否
6. 持ち物（アフィ枠）・近くで食後に行ける場所（今日の流れへ）・修正依頼フォーム

### 鮮度・整合性の運用
- 全ページに`verified_at`と確認手段を明示。情報の出どころを「公式サイト/実訪問/電話確認」で区別表記
- 修正依頼フォーム常設 → 施設からの指摘は48時間以内反映 → 「施設確認済み」バッジ化（クレーム対応を信頼資産に転換する）
- 口コミは集めない。「実用情報の正確さ」一本。UGCの管理コストは少人数運営で死ぬ

## 10. 運用体制（週10〜15時間想定）

### 週間配分
- 記事制作: 4h（AIドラフト→人間が事実確認・公式照合→公開。週2〜3本）
- GSC分析・CTR改修: 2h（週1回、kyounoko-seoスキルで定型化）
- 公式情報照合・修正対応: 2h（verified_at期限切れの棚卸し月1＋修正依頼48h対応）
- 施設営業: 2h（週3件ペースでパイロット30件を消化。深追いしない）
- 開発改善: 3h（計測→LINE→保存の順）

### AIに任せる / 人間がやる
- AI: 記事ドラフト、GSCレポート、公式サイトとの差分検知、タイトル案、内部リンク監査、噴出クエリの検知
- 人間: 公式情報の最終確認（電話・実訪問）、施設とのやり取り、収益判断、「失敗ポイント」の実体験部分

### やめる作業
- スポットページの新規大量生成（流入ゼロの資産を増やさない）
- 全スポットの鮮度維持（外食チェーン＋流入のあるページだけ守る）
- Pinterest手動運用（月1棚卸しに格下げ）

### 品質チェックリスト（公開前）
① 公式サイトで価格・メニュー名を確認したか ② verified_atを入れたか ③ 判定ボックスが1画面目にあるか ④ 失敗ポイントを最低2つ書いたか ⑤ 比較ハブ・年齢ハブへのリンクがあるか ⑥ CTA(生協orホットペッパー)は記事中盤にあるか ⑦ カニバリ（同クエリの既存記事）がないかGSC照合したか

## 15. 厳しめの最終判断

- **続ける価値: ある。ただし「おでかけサービスの夢」は一旦捨てること。** 3ヶ月の実データは「外食攻略メディア」として伸びろと言っている。夢を追ってスポットDBに時間を使えば、勝っている外食の複利を殺す
- **絞る先: 0〜2歳×子連れ外食。** 迷ったらこの層の不安を減らすかで判断
- **今すぐやめること: スポット新規追加と全方位の鮮度維持**
- **最初の勝ち筋: 「チェーン外食×子連れ設備」の日本一のDBになること。** 競合空白・実証済み・少人数向き・B2Bへの伸びしろ、全て揃っている
- **一番足りないもの: 再訪理由と収益単価。** SEOは伸びているが、読者は答えを得て去り、¥110の予約導線しかない。LINE×生協アフィがこの2つを同時に埋める
- **SEOサイトで終わらせないために**: ①構造化DB（記事の束ではなく、チェーン×店舗×設備のデータとして持つ）②LINEというオウンド接点 ③「公式確認済み」の信頼バッジ。この3つがコモディティ記事サイトとの差になる
- **収益化の距離感: 月1万円まで2ヶ月、月5万円まで6ヶ月、月30万円まで12〜18ヶ月、月100万円は24ヶ月＋B2B成立が条件。** アフィだけで100万は構造的に無理で、DB資産をB2B(タイアップ・データ提供・送客契約)に転換できるかが勝負
- **夫婦・少人数での最適な戦い方: 「狭く・深く・構造化」。** 人力調査で広さを競わず、AIで供給し人間は事実確認と関係構築だけをやる。営業は型化して週2h以内。これ以外の戦い方はすべて大手の土俵
