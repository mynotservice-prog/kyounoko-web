# スポット新規作成の情報粒度（基準）

新しくスポットを作るとき（`/admin/spots/new`、`lib/spots-extra/*.ts`、`admin-created.json` のどれで足す場合も）の、項目ごとの書き込み量と書き方の基準。
お手本は運営者が 2026-09-27 に作成した **Kids Base（キッズベース）**（`lib/spots-extra/admin-created.json` の tokyo、コミット b4061cdbb）。迷ったらこのレコードと同じ密度で書く。

事実の扱いは `docs/writing-rules.md` が正本。この文書は「どの欄に、どこまで書くか」だけを決める。

## 大原則（Kids Base がやっていること）

1. **書いたことは全部、公式の記載から。** コミットメッセージに出典URLと確認日を書く（例: 「公式サイト https://www.kidsbase.club/ ・2026-09-27確認」）。
2. **公式に無いことは「公式記載なし」と書くか、書かない。** 推測で yes／no を埋めない。例: 「ベビーカーの置き場・エレベーターは公式記載なし。」
3. **数字には単位と条件を付ける。** 「円」「税込」「1時間」「延長15分」「◯歳以上」「土日祝は+330円」まで書く。
4. **確認日は `facilities.note` の括弧に入れる。** 例: 「（2026-09-27確認）」。

## 項目ごとの基準

|---|---|---|---|

| `category` / `place` | ○ | 実態に合わせる（屋内施設なら indoor / indoor） | indoor / indoor |

## 2026-10-02 の料金監査で分かった、やってはいけない書き方

KV 上書きの41件を公式と照合したところ、次の誤りが繰り返し出た（`reports/kv-fix-list-2026-10-02.md`）。

- **乳児欄に根拠のない「無料（◯歳以下）」を入れない。** 公式が「幼児（4歳以上）◯円」と有料区分しか書いていない施設が多い。公式に無料の記載がなければ「公式サイトで確認」とする（空欄にすると元データの値が出る経路があるため）。公式FAQに「3歳から料金が必要」とあれば無料と書いてよい。
- **数字だけ（「1000」「800（４歳以上）」）で保存しない。** 必ず「1,000円」。全角数字は使わない。
- **範囲を逆に書かない**（「3,600〜1,800円」）。変動価格で上限が公式に無ければ「1,800円〜」。
- **区分を公式に合わせる。** 公式に無い区分（例: 幼児400円）を作らない。「無料（中学生以下）」のように条件付き（都内在住のみ等）の無料を一般化しない。
- **読者向けでない文を入れない**（「学生料金はFAQ記載」）。その金額を調べて書く。
- **改定日を確認する。** 4月や10月に料金改定する施設が多い（こどもの国 2026-04、東京ドイツ村は季節料金）。期間で料金が変わるなら両方を期間付きで書く。
- **括弧の対応を確認する**（「…割引あり）」の閉じすぎ）。

## 作成後のチェック

- `pricing` の各欄に「円」があるか、全角数字が無いかを目で確認する。
- `relatedArticleSlugs` が実在するかを確認する（`content/articles/<slug>.md`）。
- 公開後、CF キャッシュが残るので必要なら本番の `POST /api/admin/purge-cf` でパージする。
