### なぜ pos 8〜9 なのか（技術面は白）

本番HTMLを確認: title / canonical / robots(index,follow) / FAQPage schema / dateModified すべて正常。
技術的な欠陥ではない。

**見つかった実際の欠陥は「支配的な検索意図が本文の深いところに埋まっていた」こと。**

クエリのサブ意図別に集計すると:

| ブランド | 支配的な意図 | imp | 記事内の該当H2の位置 |
|---|---|---|---|
| コメダ | **時間（何時まで/何時から）92%** | 52,626 | **11個中6番目・本文59%地点** |
| 星乃 | 時間 9,418 ／ 曜日 7,103 ／ メニュー 5,540 ／ 値段 3,418 | | 時間は**12個中6番目・34%地点** |

一方、2026-08-24 のスプリント1で書き直した dennys / gusto は**時間が1番目**にある。
つまり**最大の2本だけが直っていなかった**。

さらに悪いことに、両方とも**先頭が「無料の正体」**だった。
「無料」の実需要は**コメダ25imp・星乃78imp**しかない。
**需要が最小の意図を先頭に、最大の意図を後半に置いていた。**

## 2. やったこと

### ① 見出しの並べ替え（需要順に組み替え）

`komeda-morning-kosodate`: 時間 → 無料 → 6通り → サイド → アレルギー → 星乃比較 → 子連れ
（時間を 6番目/59%地点 → **1番目/6%地点**へ）

`hoshino-morning-kosodate`: 時間 → 平日と土日祝 → 値段・メニュー一覧 → 実質無料 → …
（時間を 6番目/34%地点 → **1番目**、曜日を **2番目**へ。どちらも実需要の上位2意図）

並べ替えで壊れた前方参照（「後述の…」）は1件修正済み。

### ② 一次データで「何時から」に直答（コメダ）

「何時まで」は公式が「毎朝開店〜午前11:00」と答えている（2026-08-27 に公式ページで再確認）。
**答えが無かったのは「何時から」のほう**——開店時刻は店舗ごとなので、従来は
「公式店舗検索で確認してください」としか書けていなかった。

公式店舗APIから**全1,044店（47都道府県）の開店時刻を全件取得して集計**した:

| 開店時刻 | 店舗数 | モーニングが使える長さ |
|---|---|---|
| 5:00 | 1店 | 6時間 |
| 6:00 | 25店 | 5時間 |
| 6:30 | 52店 | 4時間30分 |
| 6:45 | 2店 | 4時間15分 |
| **7:00** | **869店（83.2%）** | **4時間** |
| 7:15〜7:40 | 27店 | 3時間20分〜3時間45分 |
| 8:00〜8:30 | 22店 | 2時間30分〜3時間 |
| 9:00〜9:30 | 26店 | 1時間30分〜2時間 |
| **10:00** | **20店** | **1時間だけ** |

判明したこと:
- **83.2%が7:00開店** → 「実質7:00〜11:00の4時間」と言い切れるようになった
- 7時前に開く80店のうち**53店が愛知県**（本拠地）。最早は名古屋・東郊通店の**5:00**
- **10:00開店の20店はすべて商業施設内**（イオンモール／ららぽーと／アリオ等）でモーニングは1時間だけ
- 定休日がある店が53店

取得スクリプトの注意: 詳細APIのペイロードは `shop` キーの下にネストしている
（トップレベルで読むと全項目が空になる。1回踏んだ）。テスト用レコード4件は除外すること。

## 3. わかった上でやらなかったこと

- **星乃の内部リンクは増やせない。** サイト1,148本のうち「星乃珈琲」に言及しているのは
  **13本だけで、うち12本はすでにリンク済み**。コメダのモーニングも10/10、デニーズ4/4、
  ガスト5/5が既済。**モーニング面のリンク余地はほぼ枯れている**——
  「被リンクが薄い」の真因は張り忘れではなく、**サイトにコーヒーチェーンの朝を扱う面が10本程度しか無い**こと。
  ここを増やすのは新規URLの話になるので、A1ゲートを含めて別途判断する。
- **タイトルは触っていない。** コメダは 2026-08-24 に変更したばかりで、3日で再変更すると測定できない。
  星乃は pos8.6〜9.2 でプレイブック §1 の「pos≥9はタイトルでは動かない」帯。
- **舎人公園のカニバリ**（記事 9,278imp/pos7.7 と /spot/-irhu 1,578imp/pos8.2 が同一クエリで競合）は
  今季の水遊びシーズンが終わっているため、来季前（2027-05頃）に回す。
- **`cocoichi-kids-menu`（11,681imp / pos5.5）は今回触らなかった。**
  支配的な意図「メニュー」に対応する見出しが1つも無い唯一の高需要記事だが、
  本文に裏取りされていない断定（メニュー名「ハッピーカレー」・400〜500円・ライス100g・
  離乳食持ち込みOK）が複数あり、**事実の検証を先にやらないと見出しだけ直すのは危険**。
  別タスクに切り出した。

## 追記（同日・イベント面）

イベント刷新の検証中に**サイトマップの欠落**が見つかった。

`app/sitemap.ts` の出力3,741URLの内訳は 駅2,092 / 記事810 / スポット787 / その他52 で、
**個別イベントページ（`/event/[slug]`）が1本も入っていなかった**（`/events` ハブのみ）。
内部リンク経由でしか発見されていない状態で、それでも90日25,954impある面。
平均順位が9〜10と沈んでいた一因はこれの可能性が高い。

**修正**: 会期終了していないイベント80本を sitemap に追加（終了済み79件は `page.tsx` 側で
noindex にしているため除外。送ると「送信済みだがnoindex」がGSCに積み上がる）。

**測定**: 2026-09-24 の効果測定時に、`/event/` 配下の平均順位が9.5前後から動いたかを見る。
動けば「発見されていなかっただけ」が裏づけられる。
